- Meta ad accounts registry (0134 crm_meta_ad_accounts, meta-ad-accounts.functions): admin adds accounts discovered via /me/adaccounts + authorized business owned/client edges (re-read server-side, never browser data); removal only unregisters in Pipeflow and keeps client links; client Meta selector uses the registry, falling back to live list while empty.
- WhatsApp campaign sends normalize contacts with phoneDigits (adds 55 to 10/11-digit BR numbers) before Evolution; failures store a short code from evolutionFailureCode (never raw bodies). Status labels derive from delivery counts (whatsAppCampaignLabel), so completed-with-errors/interrupted need no new state; pacing chosen at creation is saved inside confirmCampaign before start.

- Client tasks (0137): deletes are soft (deleted_at; every list read filters it, AI dedupe still sees them); a trigger writes crm_client_task_events for create/change/complete/reopen/delete; bulk actions and manual order go through service-only RPCs, with order stored per context (central / client:<id>) in crm_task_orders so reordering never touches status or audit. TaskBoard is the shared list UI.
- B2B e-mail-list origin (EmailListImport, b2b-email-list.ts, 0139): source "lista" companies may skip CNPJ/placeId only with name + e-mail; import_b2b_companies also dedupes them by lead name/company. Parsing/validation is browser-only; cards are created only after explicit confirmation, never sends.
